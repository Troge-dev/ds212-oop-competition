PILLAR 01 · DEEP DIVE

Encapsulation: Visibility Tiers & Name Mangling

ENCAPSULATION 1/2

Python does not use private or protected keywords like Java or C++. Instead, it combines naming conventions, compiler name mangling, and @property descriptors.

Python Attribute Visibility Levels
Syntax Visibility Level Python Runtime Behavior When to Use in DS212
self.name Public Accessible and writable directly from anywhere. Simple, unvalidated data or public @property interfaces.
self._hp Protected (Convention) Accessible if forced, but signals internal ownership ("do not touch directly"). Backing storage behind @property getters and setters.
self.__pin Private (Name Mangled) Python rewrites the name internally to _ClassName__pin to prevent accidental collisions in subclasses. Internal invariants that subclasses must never accidentally overwrite.
KEY INSIGHT · THE PYTHONIC WAY

Expose clean attribute syntax (station.threshold = 120) backed by @property and @threshold.setter. Callers get simple syntax, while your class silently enforces validation rules.

Encapsulation protects invariants at write-time and read-time DS212 Standard: _protected + @property
PILLAR 01 · CODE ANATOMY

Enforcing Invariants & Preventing Mutable Leaks

ENCAPSULATION 2/2
BROKEN DESIGN (LEAKY STATE) 
class WeatherStation:
    def __init__(self, threshold):
        self.threshold = threshold
        self.readings = []

s = WeatherStation(-999)      # Corrupt state allowed
s.readings.append("bad_data") # Bypassed validation!

Even if you add a record() method, returning the raw self._readings list still lets callers run .append() or .clear() from outside!

ENCAPSULATED DESIGN (DEFENSIVE) 
class WeatherStation:
    def __init__(self, threshold):
        self.threshold = threshold  # Calls setter!
        self._readings = []

    @property
    def readings(self):
        return tuple(self._readings) # Read-only copy

    @property
    def threshold(self):
        return self._threshold

    @threshold.setter
    def threshold(self, val):
        if not (0 <= val <= 500):
            raise ValueError("Out of range")
        self._threshold = val
Task 1 Tip: Always return tuple(self._list) for read-only collection properties Validation belongs inside __init__ and setters
PILLAR 02 · DEEP DIVE

Inheritance: Reusing State with super()

INHERITANCE 1/2
THREE SUBCLASS ACTIONS
  • 1. Inherit: Use a parent method untouched (e.g., Warrior inherits take_damage() and .hp for free).
  • 2. Override: Redefine a method completely to specialize math or rules (e.g., Mage.attack() uses spell_power * 2).
  • 3. Extend: Call super().method() inside the child method to reuse parent logic and add extra behavior.
CRITICAL RULE

If a subclass defines __init__ without calling super().__init__(...), none of the parent's attributes (_name, _hp) are created—causing AttributeError!

OVERRIDE + EXTEND EXAMPLE 
class OrderTicket:
    def __init__(self, ticket_id, rate):
        self._ticket_id = ticket_id
        self._rate = rate

    def summary(self):
        return f"Ticket #{self._ticket_id}"

class StudentOrder(OrderTicket):
    def __init__(self, ticket_id, rate, campus_id):
        super().__init__(ticket_id, rate)  # Setup parent
        self.campus_id = campus_id

    def summary(self):                   # Extend
        base = super().summary()
        return f"{base} | Student {self.campus_id}"

PILLAR 03 · DEEP DIVE

Polymorphism: Four Mechanisms in Python

POLYMORPHISM 1/3

Polymorphism means "many forms"—a single symbol, function, or interface behaving appropriately depending on the object it receives. In Python, polymorphism shows up in four distinct ways:

01 · FUNCTION POLYMORPHISM
One Function, Multiple Data Types

Functions like len(x), sum(x), or sorted(x) accept strings, lists, tuples, dicts, or custom objects without separate len_str() / len_list() names.

02 · OPERATOR POLYMORPHISM
Operator Overloading (+, *, ==)

Built-in operators adapt to their operands (+ adds integers, concatenates strings, joins lists) and can be customized via dunder methods like __add__.

03 · SUBTYPE POLYMORPHISM
Inheritance + Method Overriding

Subclasses share a parent interface (attack(), late_fee()) so a loop processes mixed objects uniformly without checking concrete types.

04 · DUCK TYPING
Behavior Over Hierarchy

"If it walks like a duck and quacks like a duck..." Unrelated classes work together seamlessly as long as they implement the expected method name.

PILLAR 03 · MECHANICS

Function Polymorphism & Operator Overloading

POLYMORPHISM 2/3
FUNCTION POLYMORPHISM (BUILT-IN & CUSTOM) 
# Same function len() works on completely different types
print(len("DS212"))          # 5 (characters)
print(len([10, 20, 30]))     # 3 (list items)
print(len({"a": 1, "b": 2})) # 2 (dict keys)

# Under the hood, len(obj) calls obj.__len__()!
class Playlist:
    def __init__(self, tracks):
        self.tracks = list(tracks)
    def __len__(self):
        return len(self.tracks)

p = Playlist(["Intro", "Lab"])
print(len(p))                # 2 (works with len()!)

Also note: Python allows type-based dispatch via @functools.singledispatch when different data types need distinct algorithms under one function name.

OPERATOR POLYMORPHISM (OVERLOADING) 
# Same '+' operator, three different behaviors:
print(10 + 5)                # 15 (int addition)
print("Data" + "Science")    # "DataScience" (concat)
print([1, 2] + [3, 4])       # [1, 2, 3, 4] (merge)

# Custom Operator Overloading with __add__:
class Vector2D:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __add__(self, other):
        return Vector2D(self.x + other.x, self.y + other.y)
    def __repr__(self):
        return f"Vector2D({self.x}, {self.y})"

v = Vector2D(2, 3) + Vector2D(4, 1)  # Vector2D(6, 4)

PILLAR 03 · REFACTORING PATTERN

Eliminating isinstance() with Duck Typing

POLYMORPHISM 3/3
ANTI-PATTERN (FRAGILE TYPE CHECKING) 
def run_battle_round(units, target):
    total = 0
    for u in units:
        if isinstance(u, Warrior):
            total += u.attack(target)
        elif isinstance(u, Mage):
            total += u.attack(target)
        # TrapTurret silently skipped!
    return total
  • Every time a new class is introduced, you must hunt down and edit every if/elif branch.
  • Breaks open-closed design and rejects valid duck-typed objects.
CLEAN POLYMORPHISM + DUCK TYPING 
class TrapTurret:  # Does NOT inherit Fighter!
    def __init__(self, damage):
        self.damage = damage
    def attack(self, target):
        target.take_damage(self.damage)
        return self.damage

def run_battle_round(units, target):
    # Works for Warrior, Mage, AND TrapTurret!
    return sum(u.attack(target) for u in units)
  • Zero isinstance() checks.
  • Future classes work automatically as long as they provide .attack(target).
