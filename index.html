THE BIG PICTURE

Remember These Three Questions

OVERVIEW
ENCAPSULATION
"Can someone mess up my data?"

Hide messy internals. Force every change to pass through a safety check first.

INHERITANCE
"Am I writing the same class twice?"

Put shared features in a parent class once, then let child classes borrow and tweak them.

POLYMORPHISM
"Can one loop handle different types?"

Give different classes the same method name so your code works without checking their types.

Shortcut summary: Encapsulation protects the code, Inheritance reuses the code, and Polymorphism connects the code cleanly.

TOPIC 01 · ENCAPSULATION

Think of Encapsulation Like an ATM

1 OF 2
An ATM does not let you open the vault and edit your bank balance directly. You must use withdraw(amount), which checks if the amount is valid first.
UNSAFE (OPEN TO BUGS) 
class Fighter:
    def __init__(self, hp):
        self.hp = hp

hero = Fighter(100)
hero.hp = -9999   # Nothing stops this!
SAFE (ENCAPSULATED) 
class Fighter:
    def __init__(self, hp):
        self._hp = hp

    def take_damage(self, dmg):
        if dmg < 0:
            raise ValueError("Invalid!")
        self._hp = max(0, self._hp - dmg)
Rule: Never let outside code corrupt an object's internal state Next: Python's 3 Encapsulation Tools
TOPIC 01 · ENCAPSULATION

The 3 Tools You Need for Task 1

2 OF 2
  • 1. Single Underscore (_hp): Tells other coders "This is internal—do not touch it directly." (Double underscore __hp hides it even harder.)
  • 2. @property + Setter: Looks like a normal variable (s.hp = 150), but secretly runs your ValueError check!
  • 3. Return a tuple(): If you store a list (self._logs), return tuple(self._logs) so callers cannot run .append() on your list.
COPY THIS PATTERN FOR TASK 1 
class Station:
    def __init__(self, limit):
        self._limit = limit
        self._logs = []

    @property
    def logs(self):
        return tuple(self._logs)  # Read-only!

    @property
    def limit(self):
        return self._limit

    @limit.setter
    def limit(self, value):
        if value <= 0:
            raise ValueError("Must be > 0")
        self._limit = value
No setter = read-only property. With setter = validated property. Next: Inheritance
TOPIC 02 · INHERITANCE

Inheritance: Build Once, Reuse Everywhere

1 OF 2

A Warrior and a Mage both need a name and hp. Put shared stuff in a parent class (Fighter), and let child classes inherit it.

ACTION 1
super().__init__()

Always call this first inside a child's __init__ so the parent sets up the shared variables for you.

ACTION 2
Override a Method

Write the same method name in the child class to replace what the parent does (e.g., custom attack()).

ACTION 3
Extend with super()

Call super().describe() inside the child, then glue extra text onto the end.

If you forget super().__init__(), the child will crash with AttributeError Next: Inheritance in 8 Lines
TOPIC 02 · INHERITANCE

Seeing super() in Action

2 OF 2
PARENT + CHILD EXAMPLE 
class Fighter:
    def __init__(self, name):
        self.name = name

    def describe(self):
        return f"Fighter: {self.name}"

class Warrior(Fighter):
    def __init__(self, name, strength):
        super().__init__(name)     # 1. Setup parent
        self.strength = strength

    def describe(self):          # 2. Extend parent
        return f"{super().describe()} | STR {self.strength}"
WHEN NOT TO USE INHERITANCE
IS-A vs. HAS-A
  • Use Inheritance for IS-A: A Warrior is a Fighter. A RainGauge is a WeatherStation.
  • Do NOT inherit for HAS-A: A Car has an Engine (store self.engine inside it instead of class Car(Engine)).
Quick check: issubclass(Warrior, Fighter) is True Next: Polymorphism
TOPIC 03 · POLYMORPHISM

Polymorphism = One Name, Many Forms

1 OF 3
Think of the "Play" button: you press "Play" on Spotify, YouTube, or a Game. Same button name, completely different work underneath.
TYPE 1
Function Polymorphism

One function like len() works on text, lists, and dictionaries without needing separate function names.

TYPE 2
Operator Polymorphism

One operator like + adds numbers, joins strings, or merges lists depending on what you give it.

TYPE 3
Class & Duck Typing

Different classes share a method name (.attack()) so one loop runs them all with zero type checks.

Python uses polymorphism everywhere—even in built-in functions and operators Next: Function & Operator Polymorphism
TOPIC 03 · POLYMORPHISM

Function & Operator Polymorphism

2 OF 3
FUNCTION POLYMORPHISM

Same len() function, 3 different types:

len("Hello")        # 5 (letters)
len([10, 20, 30])   # 3 (list items)
len({"a": 1})       # 1 (dict keys)

# Make len() work on YOUR class with __len__:
class Team:
    def __init__(self, members):
        self.members = members
    def __len__(self):
        return len(self.members)
OPERATOR POLYMORPHISM (OVERLOADING)

Same + operator, 3 different jobs:

2 + 3               # 5 (math addition)
"DS" + "212"        # "DS212" (join text)
[1] + [2]           # [1, 2] (merge lists)

# Make '+' work on YOUR class with __add__:
class Wallet:
    def __init__(self, cash):
        self.cash = cash
    def __add__(self, other):
        return Wallet(self.cash + other.cash)
You give your own classes built-in superpowers using __dunder__ methods! Next: Class Polymorphism & Duck Typing
TOPIC 03 · POLYMORPHISM

Stop Using isinstance() — Use Duck Typing

3 OF 3
OLD WAY (BREAKS ON NEW CLASSES) 
for unit in team:
    if isinstance(unit, Warrior):
        unit.attack(boss)
    elif isinstance(unit, Mage):
        unit.attack(boss)
    # What if we add TrapTurret? Skipped!
POLYMORPHIC WAY (WORKS FOR ALL) 
class TrapTurret:   # NOT a Fighter!
    def attack(self, target):
        target.take_damage(10)

for unit in team:   # Zero type checks!
    unit.attack(boss)
Duck Typing in 1 Sentence: Python doesn't care if TrapTurret has the right parent class—as long as it has an .attack() method, the loop treats it just like a Fighter.
